# バイザーモード（試作）

iTerm2 のホットキーウィンドウのように、どのアプリを使っていてもホットキーひとつで
エディタを画面に重ねて出す機能。実装は `src-tauri/src/visor.rs` と `src/App.tsx`（`visor` プロップ）。

## 挙動

- ホットキー（既定は `⌥Space`、環境設定で変更可）で開閉する。`Esc` でも閉じる（IME 変換中の `Esc` は変換の取り消し）
- マウスカーソルのある画面全体を覆う。0.2 秒でフェードインする（閉じるときは即座に消える）
- 他アプリのフルスクリーン画面の上にも重なる。閉じると元のアプリに入力が戻る
- メイン画面を `Cmd+W` で閉じてもアプリは終了しない（バイザーが残るため）。Dock アイコンでメイン画面を作り直す
- バイザーはメイン画面と同じファイルを開く。メイン画面で書いていたものがバイザーに出て、バイザーで書いたものは
  閉じたあとメイン画面に出る。バイザーで `Cmd+O` や `Cmd+N` でファイルを替えると、メイン画面もそのファイルになる
- 受け渡しのたびにキャレット位置を引き継ぐ。内容が変わっていたほうの画面はエディタを作り直すので、
  取り消し（`Cmd+Z`）の履歴は消える（内容が同じなら残る）
- 環境設定（`Cmd+,`）はメイン画面でだけ開く
- バイザーが出ているあいだにメイン画面をクリックすると（別のディスプレイなど）、バイザーは隠れる
- Dock からメイン画面を開き直すと、最後に開いていたファイルを開く

## 仕組み

- バイザーは別のウィンドウ（ラベル `visor`）。同じ `index.html` を読み、メイン画面と同じ `App` を `visor` 付きで動かす。
  権限（capabilities）もメイン画面と同じ
- tauri-nspanel で NSPanel に変換し、nonactivating + fullScreenAuxiliary + canJoinAllSpaces にする。
  アプリをアクティブにしないので、他アプリの Space に切り替わらずに重なる
- ウィンドウレベルは Status（25）。メニューバー（24）と常時表示の Dock（20）より上に出て、画面全体を覆う。
  IME の変換候補の窓はさらに上に出る（実機で確認済み）
- ホットキーは tauri-plugin-global-shortcut（Carbon の `RegisterEventHotKey`）。アクセシビリティ権限は不要。
  メイン画面が設定を読んだ時点で `set_visor_shortcut` コマンドで登録する。設定画面でキーを記録している間は外す
- tauri-nspanel が macOS の非公開 API を要するため `macOSPrivateApi: true`（Mac App Store には出せない）

## メイン画面との受け渡し（バトン）

両方の画面が同じファイルをオートセーブすると、古い内容でもう一方の編集を上書きしてしまう。
そこで保存してよいのは「バトン」を持っている画面だけにする。vault への書き込みはすべて
`src/lib/vaultWrite.ts` を通し、バトンを持っていない画面からは書けない（eslint で直接の書き込みを禁止している）。
バトンはバイザーが隠れているあいだはメイン画面、出ているあいだはバイザーが持つ。

1. Rust が手放す側に `baton-release` を送る
2. 手放す側は保留中のオートセーブを確定させ、保存を止めてから `release_baton` を呼ぶ（ファイル名とキャレット位置を渡す）
3. Rust がパネルを出す（隠す）。受け取る側に `baton-acquire` を送る
4. 受け取る側はファイルを読み直し（手元と同じ内容なら読み直さない）、キャレットを置き直してから保存を再開する

- イベントはウィンドウの `listen` で受ける。`@tauri-apps/api/event` の `listen` は、ほかのウィンドウ宛ての
  `emit_to` まで受けてしまう
- 受け渡しの途中（Rust の `Showing` / `Hiding`）はホットキーを受けない
- メイン画面が 1 秒以内に手放さなければ、バイザーは出さない（保存を確定できたかわからないため）
- バイザーが 2 秒以内に手放さなければ、待たずに隠す（隠せないと画面がふさがったままになる）。
  このときバイザーの直前の入力がメイン画面に届かないことがある
- 画面の JS が受け渡しのイベントを聞けるようになったら `baton_ready` を呼び、バトンを持っているか確かめる
  （起動直後や Dock から開き直したとき、聞き始める前に送られたイベントは届かないため）
- メイン画面を閉じるときも保存を確定させて `release_baton` を呼び、開いていたファイルを Rust に覚えさせる
- バイザーの `Cmd+W` は閉じずに隠す
- 照合（reconcile）はファイルを書き換えることがあるのでメイン画面だけで行う。
  バイザーは初めてバトンを受け取ったときにデータベースを開く（起動時に同時に開くと初期化がぶつかる）
- 設定を保存したら、メイン画面から `settings-changed` でバイザーに知らせる
