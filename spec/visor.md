# バイザーモード（試作）

iTerm2 のホットキーウィンドウのように、どのアプリを使っていてもホットキーひとつで
エディタを画面に重ねて出す機能。実装は `src-tauri/src/visor.rs` と `src/App.tsx`（`visor` プロップ）。

## 挙動

- 環境設定で決めたホットキー（例: `⌥Space`）で開閉する。`Esc` と `Cmd+W` でも閉じる（IME 変換中の `Esc` は変換の取り消し）。
  `Cmd+Tab` などでほかのアプリに切り替えたときも隠れる
- バイザーは環境設定でオンにしたときだけ使える（初期値はオフ）。オフのあいだはホットキーを登録しない。
  macOS のホットキーは他のアプリと同じキーでも登録が失敗しないので、勝手に登録すると他のアプリのショートカットや
  `⌥Space`（英字配列ではノーブレークスペースの入力）を黙って奪ってしまう。ホットキーの初期値は `⌥Space`
- マウスカーソルのある画面全体を覆う。出るときは「背後の画面がぼける → 塗りつぶされて何も見えなくなる → 本文がぼけた状態からピントが合って出る」を
  少しずつずらして重ね、消えるときはその逆順にする（それぞれ 1 秒。expo のイージングで、最初に大きく動いてゆっくり落ち着く）。
  途中で反対の操作をしても、その時点の見た目からつながる。実装は `src/lib/visorTransition.ts`
  - 本文とタイトルのピントは、ぼけた影（`text-shadow`）とくっきりした文字の濃さを入れ替えて合わせる。
    `filter: blur` は小さい半径を指定しても一定以上ぼけて描かれ、外す瞬間にカチッと切り替わるので使わない
  - 本文のピントは 1.8 秒かけて合わせる（expo なので、0.6 秒ほどでぼけはほとんど見えなくなり、あとは余韻）
  - ピントが 9 割合うまではキャレットを隠す（キャレットは文字と違ってぼけない。合い切るまで待つと 2 秒以上見えない）
- 隠れているあいだ（ほかのアプリを使っているときなど）WebKit は描くのを止めていて、出した最初の 1 コマが灰色になる。
  そこでパネルは透明（不透明度 0）のまま出し、画面の JS が 1 コマ描いたと知らせてきたら（`visor_ready`）見せる
- 前に出るたびに、隠れる前にフォーカスがあった所（はじめは本文）へフォーカスを戻す。
  WebKit はウィンドウが前に出るとフォーカスを先頭の入力欄（タイトル）へ移してしまう
- 消える演出の途中で出し直すときは、パネルをいったん画面から外してから出す。出たままのパネルをキーにしても
  キー入力を受け取れない（Sate を前面にしないパネルは、画面に出るときにだけ受け取る）。そのため一瞬だけ背後の画面がそのまま見える
  - 閉じてすぐ（0.2 秒ほどで）出し直すと、直後のキー入力がまれに届かない（クリックすれば入る）。閉じたときに
    キー入力を下のアプリへ返す処理が、macOS 側で遅れて効くため。閉じたらすぐ下のアプリで入力できることを優先して、受け入れている
- 他アプリのフルスクリーン画面の上にも重なる。閉じると元のアプリに入力が戻る。消える演出の途中でも、
  クリックとキー入力はすぐ元のアプリ（下にあったのがメイン画面ならメイン画面）へ戻る
- メイン画面の `Cmd+W` は、ウィンドウを閉じずに、全画面を解除してから画面から外し、Sate ごと隠す（`src-tauri/src/main_window.rs`）。
  全画面スペースも消える。Dock アイコンや `Cmd+Tab` で Sate が前面に来るとメイン画面が出て全画面に戻り、
  取り消し履歴とキャレット位置もそのまま残る。隠れているあいだもバイザーは使える。
  - ウィンドウを壊すと、作り直すたびに閉じたウィンドウが macOS 側に残る（tao が解放しない）
  - 全画面のウィンドウだけを隠すと、空の全画面スペース（真っ黒な画面）が残る。アプリごと隠しても Mission Control に残る
  - アプリを隠すだけだと、バイザーを出したときに macOS がアプリの隠れた状態を解き、メイン画面がデスクトップに戻る
    （透明なので見えないが、クリックを受けてしまう）。そのためウィンドウも画面から外し、Sate が前面に来たとき
    （`NSApplicationDidBecomeActiveNotification`）に出す。バイザーは Sate を前面に出さないので、その出し入れでは戻らない
  - 全画面の解除と再開をはさむと WebKit がフォーカスをタイトル欄に移すので、戻ったら隠す前の要素にフォーカスを戻す
  - 解除のあいだは透明にして、枠付きのウィンドウを見せない。戻すときは見えるようにしてから全画面にする（macOS 標準の広がるアニメーション）
- バイザーはメイン画面と同じファイルを開く。メイン画面で書いていたものがバイザーに出て、バイザーで書いたものは
  閉じたあとメイン画面に出る。バイザーで `Cmd+O` や `Cmd+N` でファイルを替えると、メイン画面もそのファイルになる
- 受け渡しのたびにキャレット位置を引き継ぐ。内容が変わっていたほうの画面はエディタを作り直すので、
  取り消し（`Cmd+Z`）の履歴は消える（内容が同じなら残る）
- 環境設定（`Cmd+,`）はメイン画面でだけ開く
- バイザーが出ているあいだにメイン画面をクリックすると（別のディスプレイなど）、バイザーは隠れる

## 仕組み

- バイザーは別のウィンドウ（ラベル `visor`）。同じ `index.html` を読み、メイン画面と同じ `App` を `visor` 付きで動かす。
  権限（capabilities）もメイン画面と同じ
- tauri-nspanel で NSPanel に変換し、nonactivating + fullScreenAuxiliary + canJoinAllSpaces にする。
  アプリをアクティブにしないので、他アプリの Space に切り替わらずに重なる
- ウィンドウレベルは Status（25）。メニューバー（24）と常時表示の Dock（20）より上に出て、画面全体を覆う。
  IME の変換候補の窓はさらに上に出る（実機で確認済み）
- ホットキーは tauri-plugin-global-shortcut（Carbon の `RegisterEventHotKey`）。アクセシビリティ権限は不要。
  メイン画面が設定を読んだ時点で `set_visor_shortcut` コマンドで登録する（オフなら外す）。設定画面でキーを記録している間は外す
- 背後のぼかしは非公開 API `CGSSetWindowBackgroundBlurRadius`（iTerm2 の背景ぼかしと同じ）。パネルを透明にして、
  画面の JS が毎コマ半径を変える。起動後に `dlsym` で探し、将来の macOS で無くなっていたらぼかさずに出し入れする
  （リンク時に結び付けると、無くなったときに Sate が起動しなくなる）。CSS の `backdrop-filter` はほかのアプリの画面をぼかせない。
  画面を撮ってぼかす方法は「画面収録」の許可が要るので使わない
- 消える演出のあいだもパネルは出したまま、Sate からキー入力を手放す（`NSApp.deactivate`）。前面のアプリは下のアプリのままなので、そちらへ戻る。
  パネルをいったん画面から外してもキー入力は戻るが、出し直すまで WebKit が中身を描かず演出が途切れる
- tauri-nspanel が macOS の非公開 API を要するため `macOSPrivateApi: true`（Mac App Store には出せない）

## メイン画面との受け渡し（バトン）

両方の画面が同じファイルをオートセーブすると、古い内容でもう一方の編集を上書きしてしまう。
そこで保存してよいのは「バトン」を持っている画面だけにする。vault への書き込みはすべて
`src/lib/vaultWrite.ts` を通し、バトンを持っていない画面からは書けない（eslint で直接の書き込みを禁止している）。
バトンはバイザーが隠れているあいだはメイン画面、出ているあいだはバイザーが持つ。

1. Rust が手放す側に `baton-release` を送る
2. 手放す側は保留中のオートセーブを確定させ、保存を止めてから `release_baton` を呼ぶ（ファイル名とキャレット位置を渡す）
3. Rust がパネルを出す（隠す）。受け取る側に `baton-acquire` を送る
4. 受け取る側はファイルを読み直し（手元と同じ内容なら読み直さない）、キャレットを置き直してから保存を再開する

- イベントはウィンドウの `listen` で受ける。`@tauri-apps/api/event` の `listen` は、ほかのウィンドウ宛ての
  `emit_to` まで受けてしまう
- 受け渡しの途中（Rust の `Showing` / `Hiding`）はホットキーを受けない
- メイン画面が 1 秒以内に手放さなければ、バイザーは出さない（保存を確定できたかわからないため）
- バイザーが 2 秒以内に手放さなければ、待たずに隠す（隠せないと画面がふさがったままになる）。
  このときバイザーの直前の入力がメイン画面に届かないことがある
- 画面の JS が受け渡しのイベントを聞けるようになったら `baton_ready` を呼び、バトンを持っているか確かめる
  （起動直後など、聞き始める前に送られたイベントは届かないため）
- メイン画面が無いとき（通常は起きない。Dock のクリックで作り直す）は、最後に受け渡したバトンをバイザーに渡す。
  作り直したメイン画面も `baton_ready` で最後のファイルを開く
- バイザーの `Cmd+W` は閉じずに隠す。枠の無いパネルはメニューの「閉じる」（`performClose:`）では閉じられないので、
  画面の JS がキーを受けて `hide_visor` を呼ぶ
- `Cmd+Tab` は macOS が受け取るのでアプリには届かない。ほかのアプリが前面に来た知らせ
  （`NSWorkspaceDidActivateApplicationNotification`）を受けて隠す（Dock のクリックなども同じ）
- 照合（reconcile）はファイルを書き換えることがあるのでメイン画面だけで行う。
  バイザーは初めてバトンを受け取ったときにデータベースを開く（起動時に同時に開くと初期化がぶつかる）
- 設定を保存したら、メイン画面から `settings-changed` でバイザーに知らせる
